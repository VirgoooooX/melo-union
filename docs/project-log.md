Use it for major updates, meaningful optimizations, and bugs that took several attempts to fix. Keep entries short and useful for future maintainers. Do not use it as a command transcript.

## Writing Rules

- Record summaries, decisions, impact, verification, and follow-up principles.
- Prefer durable facts over step-by-step debugging history.
- Keep sensitive data out: no tokens, cookies, API keys, private URLs, or raw credentials.
- Avoid long logs, full command output, temporary errors, or one-off experiments.
- Link deeper notes when a topic needs more detail.

## 2026-07-07

### Android Notification Media Controls Restored

Summary:

- Fixed mobile playback not reliably showing Android notification shade media controls.
- Added an Android notification permission bridge so Android 13+ can show playback notifications.
- Simplified mobile background playback to use `just_audio_background` as the single system media session source.
- Removed the unused custom Media3 playback service and platform playback bridge to avoid split playback sessions.

Why it mattered:

- The previous shape risked two playback sessions: the Flutter `just_audio` player was the real audio source, while a separate native ExoPlayer service could become the system-facing media session.
- Keeping one media session source makes notification controls, lock-screen controls, and background playback behavior easier to reason about.

Verification:

- `flutter test`
- `flutter analyze`
- `flutter build apk --debug`
- GitHub Release `v0.5.1` built Android and Windows artifacts successfully.

Follow-up principle:

- Future mobile playback work should first check whether `just_audio_background` can own the system media session before adding another native playback service.
