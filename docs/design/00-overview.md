# 00 · 信息架构与页面地图

## 1. 核心导航原则

桌面端左侧导航只承载**一级任务**，不重复展示各音乐 Provider：

```text
喜欢
歌单
推荐
────────
下载
设置
```

Provider 是当前内容的来源维度，不是与“喜欢 / 歌单 / 推荐”并列的全局任务。因此它始终出现在对应页面的内容区顶部 Tabs 中。

## 2. Provider Tabs

| 一级页面 | Tabs 顺序 | 默认 Tab | 参与规则 |
|---|---|---|---|
| 喜欢 | 全部喜欢 / 网易云 / QQ音乐 / 更多平台 | 全部喜欢 | `readFavorites = true` 的已启用且已登录 Provider 参与“全部喜欢” |
| 歌单 | 本地歌单 / 网易云 / QQ音乐 / 更多平台 | 本地歌单 | 本地始终存在；远端 Tab 仅在 `readUserPlaylists = true` 时显示 |
| 推荐 | 网易云 / QQ音乐 / 更多平台 | 首个可用 Provider | 仅显示 `readDailyRecommendations = true` 的 Provider |

“更多平台”展示为可横向滚动的 Tab、下拉菜单或溢出 Sheet，取决于当前可用 Provider 数量。禁止把固定的 QQ/网易云分支写入页面业务逻辑。

## 3. 页面地图

```text
Desktop
├─ 喜欢
│  ├─ 全部喜欢（虚拟联合视图）
│  ├─ 单 Provider 喜欢
│  └─ 歌曲详情 / 多来源收藏状态
├─ 歌单
│  ├─ 本地歌单
│  ├─ 单 Provider 歌单
│  └─ 歌单详情
├─ 推荐
│  ├─ 当前 Provider 推荐流
│  └─ 推荐模块详情
├─ 下载
└─ 设置

Android
├─ 喜欢
├─ 歌单
├─ 推荐
├─ 搜索
└─ 我的
   ├─ 下载
   ├─ Provider 管理
   └─ 设置
```

Android 的“我的”承担桌面端“下载 / 设置”的收纳入口；不必把桌面侧栏原样缩到手机。

## 4. 固定区域

### Windows

```text
┌────────────┬──────────────────────────────┬──────────────────┐
│ 一级侧栏    │ 内容区：Tabs + 页面内容       │ 正在播放 / 队列   │
│ 208 px     │ 自适应宽度                    │ 300 px            │
├────────────┴──────────────────────────────┴──────────────────┤
│ 全宽底部播放条（76 px）                                        │
└──────────────────────────────────────────────────────────────┘
```

- 内容区**不放大型“喜欢 / 歌单 / 推荐”标题**；Tabs 从内容区顶部直接开始。
- 右栏在宽屏下固定展示当前播放和简版队列；窗口宽度不足时收为抽屉。
- 底部播放条跨越侧栏、内容区和右栏，避免割裂播放器状态。

### Android

```text
┌────────────────────────────┐
│ App Bar：小标题 + 搜索/菜单 │
├────────────────────────────┤
│ Provider Tabs               │
├────────────────────────────┤
│ 当前一级页面内容             │
├────────────────────────────┤
│ Mini Player（播放时出现）   │
├────────────────────────────┤
│ Bottom Navigation           │
└────────────────────────────┘
```

移动端 App Bar 可使用小型页面标题帮助定位，但正文内容区不再重复大型标题。

## 5. 路由建议

```text
/favorites?provider=all|netease|qq_music|...
/playlists?provider=local|netease|qq_music|...
/recommendations?provider=netease|qq_music|...
/search
/downloads
/settings
/player
```

路由 query 使用稳定的 `ProviderId` 字符串。页面展示名、图标和能力从 `ProviderDescriptor` 读取，不以路由值硬编码。

## 6. 响应式规则

| 宽度 | 形态 | 规则 |
|---:|---|---|
| ≥ 1280 px | 完整桌面 | 一级侧栏 + 内容区 + 右侧播放栏 + 全宽播放条 |
| 960–1279 px | 紧凑桌面 | 侧栏缩窄；右侧播放栏可收为可展开面板 |
| 600–959 px | 平板 / 窄窗口 | 侧栏收为 Rail 或抽屉；内容区单列；队列由底部 Sheet 承载 |
| < 600 px | Android 手机 | Bottom Navigation + 横向 Tabs + Mini Player |

## 7. 不可违反的规则

1. Provider 不得在侧栏与内容 Tabs 中重复占位。
2. “全部喜欢”只聚合具备读取收藏能力的来源；本地歌单不混入“全部喜欢”。
3. 收藏动作始终写回 `favoriteTargetRef.provider`，不能因播放换源改变。
4. 无法写收藏、未登录、不可播放、不可下载必须显式解释，不能显示伪可用按钮。
5. 同曲多来源在 UI 上可合并，但来源收藏状态必须独立保留。
