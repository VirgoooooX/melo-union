# 安全、隐私与数据边界

## 一、敏感数据分类

| 类型 | 示例 | 存储位置 | 禁止事项 |
|---|---|---|---|
| 登录凭证 | Cookie、令牌、会话密钥 | 系统安全存储 | SQLite、日志、同步、上传 |
| 临时授权 | 播放/下载 URL、Headers、过期时间 | 内存短期缓存 | 持久化、同步、分享 |
| 业务元数据 | 本地歌单、隐藏规则、播放历史 | SQLite | 包含凭证 |
| 文件数据 | 下载音频、封面、歌词 | 用户选定目录 / App 媒体目录 | 默认上传 |
| Provider 代码 | 内置适配包、请求协议实现 | 随应用编译与签名发布 | 在线下载、远程执行、未审计脚本 |

## 二、必须遵守

- 网络日志默认关闭；调试日志也要脱敏 Cookie、Authorization、二维码会话参数。
- SQLite 数据库不存登录凭证。
- WebDAV 或未来的任何同步系统不传递登录凭证、临时票据或音频文件。
- UI 不显示完整 Cookie、令牌或可复用授权链接。
- 退出账号时删除对应安全存储、内存缓存和私有快照。
- 不运行公网可访问的本地代理服务器。
- 不使用公共共享 Cookie、公共账号池或第三方代登录服务。
- Provider 只能作为内置、随 App 版本编译并签名发布的代码包接入。
- 不从网络热加载 Dart 代码、动态库、Provider 脚本或远程配置来改变认证、签名、请求和播放逻辑。
- Provider 发生协议异常时，优先禁用对应能力并提示维护中；不得以未知替代逻辑继续处理用户会话。

## 三、Provider 最小权限原则

每个 Provider 只应持有实现其已声明能力所需的会话与请求信息：

- Provider 间不得读取彼此的 Cookie、token 或账户缓存。
- 只读 Provider 不应暴露写收藏、写歌单等入口。
- 无下载能力的 Provider 不应生成或缓存下载任务。
- Provider 的错误日志必须以 `ProviderId` 和脱敏错误码定位，不输出原始授权数据。
- Provider 被禁用、弃用或登出时，应清理其私有安全存储与短期票据，但保留不含凭证的本地歌单引用和缓存元数据。

## 四、平台边界

MeloUnion 的设计目标是统一体验，不是规避平台限制。下载、播放与收藏操作仅应基于当前账号在平台允许范围内获得的能力。

当平台不可用、账户无权限、内容受地区/会员/版权限制或协议发生变化时，应用应明确提示，而不是伪造成功状态或尝试规避限制。
